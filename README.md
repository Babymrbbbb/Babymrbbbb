# 用 AI 重构门店运营落地模式

我是 47 家烘焙连锁门店的用户运营负责人。我把运营里每天重复发生的劳动，一件一件改造成由 AI 驱动的自动化运营分析——现在这套东西每天在公司里真实运行，不是演示。

**[→ 读完整落地复盘](https://Babymrbbbb.github.io/article.html)**（背景、数据、分析、结果、AI 边界与 Agent 搭建）

---

## 一、背景：我面对的是什么

我负责一家烘焙连锁品牌的用户运营，门店分布为清远（含连州）40 家、广州（含花都）4 家、肇庆 2 家、佛山 1 家，合计 47 家，服务约 20 万终端客户。

这份工作真实的困难不在策略，而在执行密度：47 家门店意味着每天有几十份数据要汇总、几十个问题要回答、几十条动作要追踪。具体卡在四个地方：

| 卡点 | 具体表现 |
|---|---|
| 数据散 | 订单、会员、客流分散在不同系统，每天手工汇总，口径还不统一 |
| 知识散 | SOP、新品资料、加盟政策散落在文档里，店长查得慢、新人靠口口相传 |
| 情报散 | 竞品动态无人持续整理，等到要用时找不到 |
| 重复劳动多 | 话术、日报、作战卡、复盘，每天重复做同样的事 |
| 数据分析浅 | 能拉出数字，但看不出原因：哪家店为什么掉、掉在哪个品类、该动哪个动作，全靠人一个个翻 |
| 落地执行断 | 分析结论停在报告里，到店长手上就变成「知道了」，谁做、什么时候做、做完没做，无人追踪 |

前四个是「量」的问题，后两个是「质」的问题。数据分析浅、落地执行断，说明整条链路缺一个闭环——分析出来的结论没有变成门店当天要做的动作，动作做完也没有回到数据里验证。

所以这件事从一开始就不是「上一个 AI 工具」，而是「重做一遍运营的落地方式」。

我的角色是一线运营负责人，不是科班工程师。所以我用 AI 的方式很直接：哪个环节每天在消耗人，就用 AI 把它接过去。

## 二、我用 AI 做了什么

改造过程分成四个阶段，每个阶段都对应一个真实发生过的故障，而不是先有技术再找场景。

### 阶段一 · 接入：让 AI 调用稳定下来

**遇到的故障**：多个模型账号配额不够，429 频繁中断，AI 一忙就不可用。

**我做的**：自建了一个本地模型网关，把多个账号聚合成一个端点，按配额自动轮询，遇到限流或失效自动切换并隔离。

**结果**：上层所有 AI 应用有了稳定底座，不再因为单个账号限流而停摆。

### 阶段二 · 用好：让 AI 产出可用

**遇到的故障**：AI 出的图、出的视频一眼就假，内容生产变成碰运气。

**我做的**：把每次成功的提示词写法沉淀成方法论——通用铁律、图像结构、视频叙事骨架，全部经过实测验证后入库，不是理论推导。

**结果**：AI 内容产出一遍过的比例明显提高，方法可复用给团队。

### 阶段三 · 知识：让答案带出处

**遇到的故障**：文档越攒越多却找不到，知识是死数据；直接问大模型会编造，因为它不知道我的业务事实。

**我做的**：搭了一套知识库系统。模型负责把上千篇原始资料编译成可导航的聚合页，检索负责精确召回，命中页作为上下文再交给模型生成带引用的答案。

**结果**：1,600 余篇原始资料被编译成 1,300 余个可导航页面，问答可以追溯来源，不再是模型凭印象作答。

### 阶段四 · 组织与交付：让 AI 真的进入业务流程

**遇到的故障**：AI 能力很多，但组织消化不了，工具之间互相覆盖，最后没人用。

**我做的**：一边把多个 AI 角色编排成有分工、有决策边界、有校验闸门的生产线；一边把高频操作做成两套 Windows 桌面软件——经营驾驶舱和调度运维工作台，双击即用。

**结果**：AI 从「偶尔试试」变成「每天打开的生产工具」。

## 三、落地结果

| 指标 | 结果 |
|---|---|
| 覆盖门店 | 47 家（清远含连州 40 / 广州含花都 4 / 肇庆 2 / 佛山 1） |
| 服务终端客户 | 约 20 万 |
| 会员复购率 | 月均提升 13% |
| 自动化任务 | 44 条，按日 / 周 / 月自动运行 |
| 知识库规模 | 1,600+ 篇原始资料 → 1,300+ 可导航页 |
| 每天在跑的桌面工具 | 2 套（经营驾驶舱、调度运维工作台） |

这些数字对应的是公司现在每天在用的系统，不是我事后整理的成果清单。

## 四、我的原则

1. **先解决故障**——每个工具都对应一个真实发生过的故障，不为了用技术而用技术。
2. **明天还会被打开**——判断价值的标准只有一个：这套东西明天还会不会有人用。
3. **能跑才算数**——一行命令能起、出问题能重跑修复，比架构图漂亮更重要。
4. **给一线用**——最终用户是店长，他们不常开电脑，所以结果要能在手机上直接执行。

我不做演示给人看的东西。47 家门店每天真的在跑，出错就是门店当天少一份作战卡、店长少一条结论。所以宁可朴素，也要能用、能修、能交给别人接手。
